## Style observations
- Only `weft source add --service` named for CloudWatch; terminology "producer" and "token" not defined in-doc.
- "as different tokens reauth over time" (line 61-62) is vague phrasing.
- Cross-ref "Meta-variables" by section name only, no link.
- Path docs here (`/log/<namespace>.log` wildcard) conflict potentially with query-logs.md `cat *.log`; check consistency.
- Env segment explanation relies on "minted with `--env`", but the doc never shows the mint command (query-logs.md does).
- No warp / Windows / "watch" / coming soon mentions. Render `cron` kind uses word cron legitimately.


## Findings

- **namespaces-09/10 (lines 18-21)**: doc says `# From the shell` / `namespace create production`. In `weft sh -c` this gives `bash: namespace: command not found`; the real command is top-level `weft namespace create --name <name>` (also `weft namespace list`). Doc at fault (or shell command missing; interactive shell not tested, 🖥). Proposed: "```\n# From your terminal\nweft namespace create --name production\n```".
- **namespaces-04 (line 15)**: doc says click **Create namespace**; the button in frontend/src/pages/Namespaces.tsx is labelled `new`. Doc stale (or UI label). Proposed: "click **new**" (confirm in browser 🖥).
- **namespaces-16 (lines 35-37)**: `/log/<namespace>.log` works as wildcard, but equivalent globs `/log/acme/*/*/main.log` fail (`no pseudofiles match`). Doc is fine; do not add a glob equivalent.
- **namespaces-22 / 25**: `/log/acme/prod.log` errors with "missing a kind segment"; `heartbeats` and `runtime` kinds not present in dev data (only `main`, `metrics`), so unconfirmed (🔒 needs weftd telemetry).
- **namespaces-40 (lines 61-62)**: "as different tokens reauth over time" is vague/ungrammatical. Proposed: "A namespace can hold both env-less and env-bearing streams, depending on how each token was minted."
- **namespaces-07/08 (line 16)**: "it becomes part of token identifiers and CLI scoping" is loose: tokens carry a NAMESPACE column and free-text label; no identifier embedding verified. Proposed: "it is used to scope tokens, sources, and log paths."
- **Doc-wide suspects**: 3-segment examples (lines 31, 42-43) are documented as env-less layout, and the dev stack only has the 4-segment layout; env-less could not be verified. Directory globs fail (confirmed). No `watch` mentions. Missing: the mint command (`weft token create --namespace NS --env ENV`) is never shown.
- [re-triaged 2026-10-12] namespaces-22 downgraded to ✅ (3-seg spans envs, 4-seg selects one); namespaces-14/21/25 stay ⚠️ (no env-less data, no heartbeats/runtime telemetry in dev). Observed quirk: 3-seg tail/cat resolve but 3-seg ls does not.
