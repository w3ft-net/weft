## Findings
Test bed: globex (dana), read-only. Cap, restore/revert/amend, vi popup, permission rows are 🔒/🖥 (steps in evidence cells).

- git-26 (lines 57-59): doc says a path "outside `/bin` and `/cron.d`" is refused, but the message (and tracked set) lists four paths. Doc stale. Proposed: "A path outside the tracked set is refused: `fatal: '/tmp/x' is outside the repository (only /bin, /cron.d, /etc/dashboards and /etc/notify.yaml are tracked)`."
- git-40/74 (lines 82, 149): doc says `^` marks lines that predate what the cap kept. Observed `^` on a file's genuine first version with no cap hit (`git blame /cron.d/mem-pressure` -> `^e1e9fed ...`). Ambiguous. Proposed: "A `^` marks a line that comes from the oldest version still kept (the file's first version, or the cap's edge)."
- git-71/73 (lines 144-147): doc sample shows first names `Bob`/`Alice`; actual shows full display name (`Dana Okafor`, `Eli Bergstrom`, `system`). Doc sample stale; use full names in the example.
- git-21 (line 51): `git log -- /log/...` is not refused by git; it fails with a planner error (`query: plan: ... pipeline must start with cat, head, or tail ... "git" can't be the first stage`). Product wart; doc doesn't claim a message, but a reader following the "outside the repository" pattern would be confused. Probably product bug (or add a note).
- git-101 (line 195): `--color=always` works for `-p`/diff but `git log --oneline --color=always` is plain (no coloured hash/decoration). Minor product gap; doc says override works generally.
- git-06/09 (lines 18-23): "behaves and prints the way git does" is broad: `git status --short`, `git log --format=...`, `git log --help` all refused; `git --help` lists commands only, no flags. Ambiguous. Suggest adding "Flags it doesn't implement are refused with `fatal: unrecognized argument`" and pointing to the flag list under `git log`.
- git-23/24 (lines 54-57): `rev:path` needs the repo-relative form: `git show HEAD:/bin/scan` -> `fatal: path '/bin/scan' does not exist in 'HEAD'`. Doc example uses `bin/scan` (OK), but the "write a path any way" sentence suggests `/bin/scan` works everywhere. Add: "(after `<rev>:` use the repo-relative form, `bin/scan`)". Bare `scan` works only after `cd /bin`, as documented.
- git-54 (line 102-103): `--since=1d` rejected (`fatal: unrecognized date: 1d`); doc only lists `"2 days ago"` and ISO dates, so doc is fine; note only.
- git-59/60: example subject `Update cron.d/errors` uses a cron name not in globex; harmless. Generated message for Create observed; Update/Delete unverified.
- git-92 (line 182): `git commit` prints "On branch main / nothing to commit, working tree clean" in red on stderr; doc says "finds nothing to commit". Fine.
- git-119 (line 238): doc says `add rm mv stash reset clean` "don't exist"; actually refused with `is a git command, but weft doesn't support it` (consistent with line 21 but not "don't exist"). Cosmetic.
- git-129/title (line 3): title/`--help` say `/etc`, only `/etc/dashboards` and `/etc/notify.yaml` are tracked. Imprecise but not wrong.
- Static: frontend/src/generated/docs/git.ts has no stray `{{PLACEHOLDER}}`; `&lt;`/`&gt;` appear only inside correctly escaped `<code>/<pre>` HTML. shell/help_corpus_gen.go has no `git` manual entry (web-only doc), so `man git` cannot be checked; `help`/`man` are 🖥.
- Style: example hashes in doc (`a4fb0c2f`, `0174c77`) are inconsistent with log sample but blame width (`^`+7 vs 8 unmarked) matches real behavior.
