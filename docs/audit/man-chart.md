## Findings

- **F1 (man-chart-03, -21, -23; lines 19, 55, 58)**: Doc lists `-t`/`--type` and `-n`/`--limit` for cron form. Actual: `chart error-rate --type bar`, `--limit 5`, `--limit=5` and `-n5` are silently ignored (line chart, "last 50"); `-t pie` silently ignored (pipe form errors with `unknown type "pie" (want line|bar|sparkline)`). Probably product bug (cron-form flag parser accepts only short forms and ignores unknown flags). Until fixed, doc text could say: "`-t <line|sparkline|bar>`, `-n <N>` (short forms only in cron form)".
- **F2 (man-chart-25, -03; line 59-60)**: `-i 50ms` and `-i abc` produce no error (even in one-shot). Minimum 100ms not enforced where tested; re-test in TTY with `-f`. Probably product gap; bare `chart` usage line also omits `-i`/`-f`.
- **F3 (man-chart-11; line 37-38)**: `... | chart | cat` yields `bash: chart: command not found`, not a message about chart being terminal. Doc fine, error misleading (product). Possible doc add: "Piping chart's output onward is an error."
- **F4 (man-chart-18, -19; line 47-49)**: Cron form needs numeric last field. `chart mem-pressure` -> `chart: no numeric results for watch "mem-pressure"` (cron ending in `jq -c | alert -k .pct`). Doc doesn't say which crons are chartable. Also usage/error text says "watch" where the doc says "cron" (usage: `chart <watch> [-t TYPE] [-n LIMIT]`; stale product string). Suggested doc: "The cron's stdout must end in a number on each line; crons that emit JSON rows (e.g. alert -k) cannot be charted."
- **F5 (man-chart-46; line 97-99)**: Comment "a quick distribution by host" but example groups by `.path`. Doc fix: "a quick distribution by path" (or use `.host`).
- **F6 (man-chart-46, -47, -49; lines 98-111)**: Examples use 3-segment `/log/myco/api/main.log` and `/log/myco/coordinator/...`; real layout is `/log/<ns>/<env>/<svc>/<kind>`, e.g. `/log/acme/prod/api/main.log`. Doc stale; also `/log/acme/prod/api/main.log` is plain text (no JSON), so `.latency_ms`/`.cpu_pct` fields will not exist for most orgs. Suggest replacing with `/log/myco/prod/api/metrics.log` JSON examples.
- **F7 (man-chart-48, -49; lines 106-111)**: `jq 'select(...)'` output is pretty-printed multi-line, and `chart -x .ts` then fails: `error: chart: x: invalid json` / `tag: invalid json`; `jq -c` or an object constructor (`jq '{ts,pct}'`) works. `jq '.pct' | chart` fails with `no data points to chart` when any row yields null. Ambiguous/product: doc examples (esp. line 110 `select(.metric=="mem_pct")`) would break. Suggest `jq -c 'select(...)'` in the example, or fix chart to accept multi-line JSON.
- **Other (man-chart-37)**: `--bucket 50ms` accepted with no minimum; doc silent. `--bucket` with default x accepted. No decision needed.
- Not verified (🖥/🔒): follow mode, keys, resize, `ls -l /cron.d/` sparkline, `man chart`/`chart --help` display, 'a 1 2 -> 2' on a real cron.
