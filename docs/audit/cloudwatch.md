## Style observations
- Line 75-77 says "there's nothing to pull on demand" but line 110-111 says `weft source resample` will "pull a fresh sample". Likely contradictory.
- Line 77 "Once enough lines have accumulated" gives no threshold.
- Line 12-16 "Kinesis Data Firehose" naming: AWS now calls it "Amazon Data Firehose" (possibly dated).
- Line 65 "agent token" term vs "namespace token" / "producer token" elsewhere; inconsistent token terminology.
- Line 63 placeholder `<your-weft-namespace-token>` differs from "namespace-scoped agent token".
- Line 93 `main.log` unexplained; other manuals use per-process names.
- Line 91-94 code block mixes a comment "# And in the shell" with a command lacking prompt.
- Line 59 template URL on `weft-public` bucket; version pinning absent. No warp/Windows/"watch"/"coming soon" mentions.


## Findings

- cw-45/cw-27 (lines 75-77 vs 110-111): doc says "nothing to pull on demand" then tells reader `weft source resample` will "pull a fresh sample". `weft source resample <namespace>/<service>` exists, its usage text says nothing about pulling. Doc internally contradictory (ambiguous; actual resample behavior unobserved). Proposed text for line 110-111: "then `weft source resample <namespace>/<service>` to discard the current sample, let a fresh one accumulate, and re-run the wizard" (only if that matches behavior; confirm with a human run).
- cw-08/cw-35 (lines 29-30, 93): doc implies 3-segment `/log/myco/my-app/main.log`. Real stack layout is 4-segment `/log/<ns>/<env>/<svc>/main.log`; `ls /log/acme/api` fails. Probably doc stale or token/env undocumented. Proposed: say "/log/<namespace>/<env>/<service>/main.log (or without <env> for an env-less token; see Namespaces)", after human confirms where CloudWatch sources land.
- cw-13 (line 43): `weft source list` shows STATUS/TYPE columns; a separate `weft source pending` subcommand exists and is not mentioned. Could add "or `weft source pending`".
- cw-29/cw-33 (line 80, 88): usage has `[--file schema.yaml]` option; doc says "no local file to manage" which is true by default but omits the option. Minor.
- cw-27/cw-41 (lines 75, 107): `weft source schema acme/api` on a configured source prints schema YAML only; no accumulation progress visible. For an unconfigured source unverified; doc claim may be unobservable.
- cw-23 (line 65): "agent token" term; `weft token create` usage has --namespace/--label/--env/--for PRODUCER; term inconsistent with other docs (style).
- Static check: generated connect-cloudwatch.ts has `&lt;`/`&gt;` inside HTML, intentional; no stray {{PLACEHOLDER}}; help corpus entry intact. Doc uses "Kinesis Data Firehose" (AWS renamed Amazon Data Firehose); `--help` is not a real flag for `weft source`, any arg prints usage.
- [re-triaged 2026-10-12] cw-35 downgraded to ✅ (3-seg cat|head works with real names); cw-08 stays ⚠️ (needs a write to observe).
