## Findings

- hcron-19 (line 27): doc example `/log/myco/api/main.log` is 3-segment; real is `/log/<ns>/<env>/<svc>/main.log` ("unknown source: myco"). Doc stale. Proposed: `cat /log/myco/prod/api/main.log | grep ERROR | wc -l`.
- hcron-26 (lines 32-34): doc says the functions read "this cron's" history; they require an explicit name (`usage: weft::latest <watch-name>`). Proposed: "read a cron's history; pass the cron name, e.g. `weft::latest error-rate`." In-cron implicit scoping untested (🔒). Usage text says "watch" (product string).
- hcron-16 (line 25): real header for cron expressions is `# schedule: */1 * * * *` in existing crons; "(or cron: */5 * * * *)" is unobserved and ambiguous in a code block. Proposed: put `# schedule: */5 * * * *` as a separate commented example once verified (🔒).
- hcron-15: `# schedule: every 1m` not observed anywhere; existing crons use `*/1 * * * *`. Verify by saving (🔒) before documenting.
- hcron-17: `# notify: ops` is not used by any existing cron; notify.yaml has `ops` so alias exists. Unverified header (🔒).
- hcron-10: `ls -l /cron.d/` under sh -c has no sparkline column; may be TTY-only. Verify 🖥.
- hcron-36: {{TIER_LIMITS}} literal in generated corpus, expanded at runtime by shell/help_provider.go helpCron(); not present in web generated docs. Doc OK; when no tier provider the shell prints "(not available in this mode...)". Verify 🖥.
