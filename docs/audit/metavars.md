## Findings

- **metavars-F1** (l.112-115, 156-158; affects 01/07): doc says meta-var filters are folded into the shard WHERE. Actual: the filter is applied before `tail`/`head`, changing semantics. `tail -n 100 main.log | awk 'LEVEL=="ERROR"' | wc -l` -> 100 (all rows ERROR), while `tail -n 100 main.log | grep -c ERROR` -> ~10; `head -n 300 ... | awk` -> 300 vs grep 27. Product bug (planner ordering; matches known tail|jq|sort ORDER BY/LIMIT issue). Recommendation: fix planner; doc not at fault.
- **metavars-19** (l.38-40): doc says untagged dims are NULL and "neither include nor exclude". Actual: empty string; `!=` includes them (`awk 'REGION!="x"' | wc -l` -> 200), jq `._region==null` false. Probably doc stale/imprecise. Proposed text: "A row that wasn't tagged with a given dimension carries an empty string. `ENV == \"prod\"` does not match it, but `ENV != \"prod\"` does."
- **metavars-36 / 29 / 55** (l.80-81, 98-99, 151): directory-level wildcards do not work. `tail -n 2 /log/acme/*/api/main.log` -> `error: expand glob: tail: no pseudofiles match`. Only filename globs (`api/*.log`) expand. Product bug or doc over-promise; recommend either implementing dir globs or removing `*/` examples and the "recipe 2" `prod/*/main.log`. Proposed replacement: use one path per service, e.g. `cat /log/myco/prod/api/main.log /log/myco/prod/worker/main.log`.
- **metavars-44** (l.114): `awk 'X ~ "string"'` (string-as-regex) never matches, for meta-vars and ordinary fields alike (`awk '$2 ~ "INFO"'` -> 0; `awk '/INFO/'` -> 5; `awk 'SERVICE ~ /api/'` -> 5). Product bug in the interpreter. Doc example should use `/regex/` form until fixed: `awk 'POD ~ /api-7f9b/'`. Also doc's `LIKE 'api-7f9b%'` prefix semantics vs awk substring semantics unverifiable (no explain).
- **metavars-51 / 52** (l.138-144): `every 1m` schedule header not exercised (existing crons use cron syntax `*/1 * * * *`); recipe emits one row per memory sample, not one per host. Proposed text: "Each tick emits one `<host> <pct>` row per memory sample; pipe through `-t 1` so alerts group by host."
- **metavars-54** (l.145-146): grouping is by the text field chosen with `-t`, not a HOST column. Proposed: "page per host independently because `-t 1` tags each row by its first field (the host)."
- **metavars-55 / 57** (l.151-167): recipes read `main.log`, which in the dev stack is plain text; `jq` meta-var access on it errors (`cannot index number with string "_level"`) or yields nothing. Doc/product ambiguous: recipe presumes JSONL main logs. Recommend noting "for JSONL streams" or demonstrating on `metrics.log`.
- **metavars-05 / 28** (l.77-81): [re-triaged 2026-10-12: kept as unverifiable] heartbeats/runtime are valid kinds (cat returns empty, no error) but dev has no telemetry emitter. Also new: metavars-29/34 remain: mid-path wildcards (`/log/acme/*/api/main.log`) do not expand, and the 3-seg path reads rows from all envs rather than a separate env-less stream.
- **metavars-33** (l.90-95): code block mixes a `weft>` prompt and `←` annotations in a block styled like real output. Minor doc style.
