## Style observations
- Tile key is `watch` while the doc and CLAUDE/memory call the feature "cron" (user-facing surfaces should say cron). The key name `watch` is a literal YAML key, but prose in line 77 correctly says "cron". Flag for possible rename/alias or note.
- Terminal `dashboard` command vs web dashboard (team.md "dashboard's Members tab") terminology collision.
- Order of sections: "TOP-LEVEL KEYS" before tile keys fine; no mention of how web UI shows dashboards (/dashboards/<name> per tour).
- Examples block uses aligned columns inconsistent with other man pages' `# comment` style (clipboard uses indented descriptions too).
- No warp, Windows, or coming-soon mentions.

## Findings
- **man-dashboard-36 / 17 (doc l.77)**: doc calls the field `watch` and says "name of an existing cron" without saying the key is literally `watch` and that `cron:` is wrong. Existing `/etc/dashboards/prod.yaml` uses `watch:`; prior audit saw `cron:` rejected (not re-tested here). Doc is ambiguous, not wrong. Proposed: "`watch` — (the key is literally `watch`, not `cron`) name of an existing cron; must exist when the file is saved."
- **man-dashboard-13 (l.36-58)**: sample references crons `pending-jobs`, `top-errors`, `disk-pct` that are unlikely to exist, so saved verbatim it will be rejected. Doc stale-ish/ambiguous. Proposed: add a line "Each `watch:` must name a cron you have already created (`ls /cron.d`)."
- **man-dashboard-43 (l.80 vs l.87)**: tile keys line says `threshold` carries `warn`, `crit`, `max`; threshold section says `max` is gauge-only. Proposed l.80: "`threshold` — (counter, gauge, sparkline) `warn` and `crit` cutoffs; gauge also takes `max`."
- **man-dashboard-40/42/44/48**: doc says `format`, `columns`, `max`, `threshold` are kind-specific; prior audit saw wrong-kind use accepted silently (format on gauge, threshold on table). Doc wording "only" suggests rejection; unverified by me. Possible product gap or doc should say "ignored".
- **man-dashboard-50**: `dashboard ops` example uses a name that does not exist here; `dashboard` itself is a TTY-only command (not found under `sh -c`), so all UI/behaviour claims (3-9, 16-25, 31, 38, 41, 45-47, 49) are 🖥 and need a human.
- **man-dashboard-55**: man page never says writing /etc/dashboards needs the `configmgr` group (alice has it in /etc/passwd). Consider a one-line note.
- Style: no warp/Windows/coming-soon mentions; terminal vs web "dashboard" terminology not distinguished (page says nothing of the web Dashboards page).
