## Style observations
- SYNOPSIS (19-21) omits `--if-zero`/`--if-nonzero` which are documented in OPTIONS and COMPOSITE PREDICATES.
- CONDITIONS lists `any` as explicit keyword; help-alerts lists "no keyword" only.
- Line 118 uses relative `myapp.log` and awk `LEVEL` (inconsistent with /log/<ns>/<svc>/ pseudofile layout elsewhere).
- Lines 107-113 option bullets are single very long lines.
- Line 81: "previous/window average" vague baseline definition.
- Line 102: refers to repo path `docs/manual/alerting-strategies.md` in a man page.
- `check_errors` pseudo-command in examples is undefined.
- No warp, Windows, "watch", coming soon.


## Findings

- **man-alert-08** (doc 31-32, 74): doc says default condition is "any" and fires on non-empty stdin. Actual: `echo x | alert` -> `alert: usage: alert [<condition>] --notify=<alias> ...` (no fire); only `alert any` or `alert --notify=<alias>` fires. Product bug (or doc caveat). Proposed doc if product stays: "If no condition is given and `--notify` is supplied, the default is `any`. A bare `alert` with neither is a usage error; write `alert any` for a dry run."
- **man-alert-52/56/58/59** (doc 118, 122, 126, 130): examples use `myapp.log`, `/log/myco/canary/main.log`, `/log/weft/shard/main.log`: all fail with `query: unknown source`. The failed query then yields empty stdin, so `alert absent` falsely fires (56). Doc stale (3-seg/nonexistent paths). Proposed: use `/log/<ns>/<env>/<svc>/<kind>` placeholders, e.g. `tail -n 500 /log/myco/prod/api/main.log | awk 'LEVEL == "ERROR"' | alert --notify=ops`. Product note: `absent` firing on an unknown-source error is a footgun. [re-triaged 2026-10-12: 52/56/58 downgraded to ✅ (placeholder paths; work with real names); only the product footgun (absent fires on unknown-source error) remains.]
- **man-alert-59** (doc 130): JSON-path example uses `jq` without `-c`; jq pretty-prints multi-line, so each line fails (`alert: skipping row with empty tag: "{"`). Doc wrong. Proposed: `| jq -c 'select(.type=="disk")' | alert above 80 -k .pct -t .host --notify=ops`.
- **man-alert-09** (doc 34): "Always passes stdin through (tee)". Observed: pass-through when not firing; when firing stdout shows only the alert message, not the input; non-numeric input errors without passthrough; `alert` mid-pipeline (`| alert ... | cat`) -> `bash: alert: command not found`. Ambiguous/doc overstates. Proposed: "When the condition is not met, stdin is passed to stdout; alert must be the last stage of the pipeline."
- **man-alert-03** (doc 19-21): shell's own usage string differs from the SYNOPSIS (shows --notify as required, -k/-t as `<N>`); unknown flags are silently ignored (`--foo`). Product/doc mismatch; ambiguous.
- **man-alert-04** (doc 19-21): `--if-zero`/`--if-nonzero` missing from SYNOPSIS though they work. Doc incomplete. Add `| alert (--if-zero <v> | --if-nonzero <v>) [--notify=<alias>]` form.
- **man-alert-50** (doc 112): `--average` without `--duration` is silently ignored. Undocumented; add "has no effect without `--duration`".
- **man-alert-48** (doc 111): `1d` is rejected (`invalid duration: 1d`); doc could say "units s, m, h only".
- **man-alert-43** (doc 110): `-k` without `-t` and several rows is not an error in the shell (each row fires); `-t` without `-k` fires "non-empty output" ignoring the condition. Doc "required" wording is stronger than behavior (collapse is a cron-only effect, unverified).
- **man-alert-06** (doc 27): could not confirm stderr vs stdout split under `sh -c` (`2>/dev/null` does not hide the message there). 🖥 human check.
- **man-alert-53..55** (doc 119-121): `check_errors` is undefined; say it is a user script in /bin, or use a concrete pipeline.
- **man-alert-38** (doc 102): refers to repo path `docs/manual/alerting-strategies.md`; end users should see `help alerting-strategies` or equivalent.
- **man-alert-60/61** (doc 136): SEE ALSO should add `man weft`, `help cron`, and a pointer to /etc/notify.yaml.
- Not confirmed doc-wide issues for this doc: bare `myapp.log` (confirmed fails, see 52), 3-segment paths (confirmed), `watch` vs `cron` (no occurrence of "watch"), durations d/w (confirmed rejected), globs and `~` (not used in this doc).
