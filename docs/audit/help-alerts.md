## Findings
- help-alerts-06 (line 19): doc says stdin always passes through. Actual: when the alert fires, stdout carries only the message (no `60`), and the rest of the script is skipped. Probably product bug (or doc overclaim; in cron the stdout may not matter). Suggest: "When the condition does not hold, stdin passes through unchanged." if behavior is intended.
- help-alerts-17 (lines 40-43): the two-line composite fails in `sh -c` (`bash: alert: command not found`). `alert` works only as the sole/last stage. Likely a product limitation outside cron bodies; doc should say "in a cron body" if that is where it works (untested, cron blocked).
- help-alerts-14 (line 30): bare `alert` is a usage error without `--notify`. Doc says "(no keyword) - any". Suggest: "`alert --notify=<alias>` (no condition) fires when stdin is non-empty."
- help-alerts-32/33 (lines 72-83): /etc/notify.yaml could not be edited by alice (admin, configmgr in passwd) in `sh -c`: `/etc: permission denied (need the configmgr group)`. Either token-group lookup bug or write-via-redirect denied; doc never mentions the configmgr requirement. Suggest adding: "Editing requires the configmgr group."
- help-alerts-01/15/52: `help` and `man` are `command not found` in `weft sh -c`; doc claims `help alerts`/`man alert`. Probably interactive-only; ambiguous.
- help-alerts-28/29 (lines 63-69): examples use /log/weft/shard/main.log, not a path customers have; `.host` vs `._host` inconsistency unverified. Suggest a generic path such as /log/<ns>/<env>/<svc>/main.log.
- help-alerts-30: `ls /etc/notify.yaml` -> "file does not exist" while `cat` works; minor product quirk.
- help-alerts-04: in `sh -c` alert message cannot be separated from stdout via 2>/dev/null; only verifiable in a cron.
- help-alerts-12/13: `rising 50` without `%` is silently accepted; `rising N%` in doc lacks angle brackets.
- Side effects: `adduser alice configmgr` (my mistake) hit a pre-existing invited "alice" row; I ran `deluser alice` then re-ran `adduser alice`, so the invite row was recreated (a new invite email may have been triggered). Net state: unchanged row.
