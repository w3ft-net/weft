- Line 29-31 says token remains visible in token table, but line 43 says "shown once" (and heroku.md says the same). Probable contradiction.
- Line 74 "an undocumented `bld`" - a user doc referring to itself as documenting something "undocumented" is odd phrasing.
- Line 38 `For:   render` has irregular spacing (alignment) and output format `Token created:` differs from heroku.md's `issued:`.
- Line 90-92 gives no number for the default rate whereas heroku.md gives 1000 events/sec.
- Line 107-111 mentions "weft's HTTP ingest endpoint" without naming or linking it.
- Line 50 placeholder `<producer>` not defined elsewhere.
- Table row 80 column widths misaligned (cosmetic). No warp/Windows/"watch"/"coming soon" mentions.


## Findings
- render-09 / render-15 (lines 29-31 vs 43): doc says token and endpoint stay visible in the token table, then says the token is only shown once. Observed: `weft token list` shows only a truncated prefix (`wft_8fec…`) plus status; the CLI says tokens "cannot be retrieved again". Doc is at fault (lines 29-31). Whether the web table shows the endpoint is 🖥-unverified. Proposed: "The token is shown only once, so copy it now. The endpoint is the same for every Render token (`render.syslog.w3ft.net:6514`), so you can always look it up here." (if the endpoint is truly constant; confirm).
- render-12 (line 38): doc sample omits the `Label: render` line the CLI prints when `--label` is given. Doc stale. Add `Label: render` after the Token line.
- render-24/25/32-34 (lines 63-67, 80-82): doc examples use 3-segment `/log/myco/myservice/web.log`, while this stack's real layout is 4-segment `/log/<ns>/<env>/<svc>/<kind>`. Line 84-85 treats env as optional; stack evidence only shows env-bound paths. Ambiguous: confirm whether an env-less Render token yields 3-seg paths. If not, doc stale.
- render-42 (line 99): "Reissue the token from Tokens": CLI only has create/list/revoke. Proposed: "Revoke and recreate the token from **Tokens** (or `weft token revoke` / `weft token create`)."
- render-04: only a TCP connect to render.syslog.w3ft.net:6514 was observed; TLS handshake unverified.
- Style (from ledger, unchanged): "an undocumented `bld`" phrasing odd; no default rate number; "HTTP ingest endpoint" unnamed in Vector bullet; `<producer>` placeholder undefined.
- Side note: my `nc -z` TCP-connect probe went to the real hostname render.syslog.w3ft.net:6514 (connect, no data sent).
- [re-triaged 2026-10-12] render-25 and render-34 downgraded to ✅; render-24 stays ⚠️ (env-less render path is correct, unobservable locally; doc's web-then-cron order is not the alphabetical order ls prints).
