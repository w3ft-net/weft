## Findings

- **funcs-12** (line 44): doc lists `weft::previous <w>` as a bash builtin. Actual: `bash: weft::previous: command not found`; Lua `weft.previous` works. Probably product bug (bash registration missing) or doc overclaims. Recommend: register the builtin; otherwise doc: "`weft::previous` is Lua-only".
- **funcs-51/52** (lines 116-121): doc examples use `period=1d window=4w` and `1w`/`8w`. Actual bash: `weft predicate: invalid period "1d"`, `invalid window "4w"`. In Lua the same call silently returns false (even with period "bogus"), so Lua and bash disagree, contradicting "the same Go implementation backs both". Doc stale vs product gap. Recommend either accept d/w units for seasonal args or replace text: "`period=24h window=672h` (four days of the same hour...)". Also note the example prose is wrong: "four values at this same hour on each of the last four days" needs window 4d, not 4w.
- **funcs-10/26** (lines 38-39, 64): "Go syntax" plus a "14d" cap; `14d`/`1d` error with `invalid duration`. Doc ambiguous; recommend "Durations are numbers with s/m/h units (no d or w): `30s`, `5m`, `24h`, `336h`; the endpoint cap is 14 days (336h)".
- **funcs-37** (lines 91-94): "on absent data ... predicates return false"; `is_absent` returns true (fires) on a nonexistent cron. Doc wording: "(except `is_absent`, which fires when data is missing)".
- **funcs-45** (line 102): default pct undocumented and a window cannot be passed without pct (`weft::is_falling c 1h` -> `invalid pct "1h"`). Recommend stating the default and showing `weft::is_rising <w> <pct> <dur>`.
- **funcs-18** (line 50): `count` returned 92 per hour for a */1 cron (mem-pressure), so it counts result rows, not runs. Ambiguous; recommend "count of results (rows) in window".
- **funcs-50** (line 112): "at least 4 same-time samples" holds for period=10m (4 needed) but period=1h window=61m fires, so samples aren't strictly one per period. Ambiguous.
- **funcs-05/55**: in `weft sh -c`, statements after a pipeline are dropped (`echo 60 | grep 6; echo mid` prints only 60), and `sh -c` exit status is always 0, so piped comparator exit codes cannot be observed non-interactively. Environment/CLI quirk, not necessarily doc. Comparator logic itself verified via `<` redirects.
- **funcs-06 / env**: `printf ... > /cron.d/x` and `> /bin/x` return "permission denied (need the cronmgr/binmgr group)" even though `id` shows alice in cronmgr and binmgr (non-interactive write path?). Only the pre-existing crons error-rate and mem-pressure were tested; has_changed-constant, is_absent-empty, previous-with-<2, zero-stddev guard, non-numeric mixes are untested.
