## Findings
- [re-triaged 2026-10-12: 02/25 now ✅ with real script /bin/count_errors] 02/25/26/29 (l.17-19, 67-79): examples reference /bin/error-rate and /bin/check; `clipboard` on a missing script errors "clipboard: no such script /bin/<name>". Doc fine as illustration; proposed addition: "The script must already exist in /bin/."
- 03 (l.19): host hardcoded w3ft.net even against dev/self-hosted; link 404s on dev API. Ambiguous; could say "(host depends on your deployment)".
- 10/21 (l.32, 53-54): non-/bin paths give "first argument must be a /bin/<name> path"; doc says "save it first" but never mentions the error text. Optional.
- 11 (l.33-34): default-range link differs from explicit `--range=1d..` link, so the default is probably stored as "current/relative" rather than a fixed window; wording "defaults to your shell's current range" is plausible but the stored form is unconfirmed (🖥).
- 14 (l.35-37): confirmed quoting is not preserved: `-- "a b" c` and `-- a b c` give the identical link deoOgPot9L. Doc correct.
- 16 (l.39-41): `--version=` gives generic "unknown option"; doc correct (not supported).
- 31 (l.35, 71-77): rule that `--range` must come before `--` is implied, not stated. Proposed: "Put `--range` before `--`; anything after `--` is passed to the script as-is."
- 38 (l.85-88): contradictory/unclear: "anyone else, signed in or not, gets 'that link doesn't exist'" then "recipient still has to be signed in". Proposed replacement: "The link does not grant access. It only opens for signed-in members of your org; anyone else gets \"that link doesn't exist\". Recipients also need the namespace permissions required to run the script. A link is safe to paste in a public channel: it carries only the script invocation, no log data." Also fix the line wrap at 87.
- 40/32 (l.81): `man clipboard` exists in corpus, but its SEE ALSO lists vi and cat which have no man pages (see docs/audit/man-clipboard.md).
